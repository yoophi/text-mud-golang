# text-mud-golang

Go로 작성한 영속형 멀티플레이어 텍스트 MUD 서버 MVP. Telnet(또는 `nc`)로 접속해
캐릭터를 만들고, 방을 탐험하고, 다른 플레이어와 대화하고, 아이템을 줍고,
적대적 NPC와 싸울 수 있습니다. 캐릭터 상태는 SQLite에 저장되어 서버를 재시작해도
위치·인벤토리·HP가 복구됩니다.

## 빠른 시작

Go 1.26 이상이 필요합니다.

```sh
make run            # 0.0.0.0:4000 에서 기본 월드로 실행
# 또는 직접 실행
go run ./cmd/mud-server -addr :4000 -db data/mud.db -world configs/world.json -operators admin
```

다른 터미널에서 접속:

```sh
nc localhost 4000
# telnet localhost 4000 도 동작
```

서버 종료는 `Ctrl-C`(SIGINT) 또는 운영자 명령 `@shutdown` — 접속 중인 캐릭터를
모두 저장한 뒤 안전하게 종료합니다.

### 실행 옵션

| 플래그        | 기본값              | 설명                                   |
| ------------- | ------------------- | -------------------------------------- |
| `-addr`       | `:4000`             | TCP 수신 주소                          |
| `-db`         | `data/mud.db`       | SQLite 데이터베이스 경로(자동 마이그레이션) |
| `-world`      | `configs/world.json`| 월드 정의 JSON                         |
| `-operators`  | (없음)              | 운영자 권한을 가질 캐릭터 이름 목록(쉼표 구분) |

## 플레이 방법

처음 접속하면 이름을 물어봅니다. 새 이름이면 생성 여부를 확인하고, 기존 이름이면
마지막 위치에서 이어서 시작합니다.

| 명령                 | 동작                                            |
| -------------------- | ----------------------------------------------- |
| `보기` (`look`, `l`) | 현재 방의 설명·출구·NPC·아이템·함께 있는 사람 표시 |
| `북쪽` `남쪽` `동쪽` `서쪽` `위` `아래` | 방향 이동 (`n`/`s`/`e`/`w`/`u`/`d`, `북`, `북쪽으로` 등 허용) |
| `이동 북쪽`          | 명시적 이동                                      |
| `말하기 <내용>` (`말`, `say`) | 같은 방 플레이어에게 말하기             |
| `줍기 <물건>` (`획득`, `get`) | 바닥의 아이템 획득 (`줍기 빵 2`처럼 번호 선택) |
| `버리기 <물건>` (`버려`, `drop`) | 소지품을 바닥에 내려놓기                |
| `인벤토리` (`소지품`, `i`, `inv`) | 소지품 목록                           |
| `공격 <대상>` (`치기`, `attack`) | NPC 공격. 시작 후 2초 간격으로 자동 전투 진행 |

- 한국어 조사는 자동으로 처리됩니다: `줍기 동전을`, `공격 쥐를` 모두 동작합니다.
- 같은 이름의 대상이 여러 개면 번호로 선택하세요: `줍기 빵 2`.
- 캐릭터가 사망하면 부활 지점에서 HP가 가득 찬 상태로 다시 시작합니다(소지품 유지).
- 전투 중이 아닐 때 HP는 서서히 회복됩니다.
- 적대적 NPC(예: 굶주린 늑대)는 방에 들어오면 먼저 공격합니다.

### 운영자 명령

`-operators`로 지정한 이름으로 접속하면 사용할 수 있습니다.

| 명령                       | 동작                              |
| -------------------------- | --------------------------------- |
| `@goto <방ID>`             | 임의의 방으로 순간 이동           |
| `@spawn <NPC> [방ID]`      | NPC 정의(ID 또는 이름) 생성       |
| `@shutdown`                | 저장 후 안전 종료                 |

`운영 goto 방ID` 형식도 동작합니다.

## 월드 정의 (`configs/world.json`)

- `startRoom` / `respawnRoom`: 신규 캐릭터 시작 방 / 사망 시 부활 방.
- `rooms[]`: `id`, `name`, `description`, `exits`(방향 → 방 ID). 방향은
  `북쪽/남쪽/동쪽/서쪽/위/아래` 만 허용됩니다.
- `items[]` + `itemSpawns[]`: 아이템 원형과 부팅 시 바닥에 놓이는 수량.
- `npcs[]`: `hp`, `damageMin/Max`, `aggressive`(선공), `respawnSeconds`(사망 후
  재생성), `wanderSeconds`(주기적 배회, 생략 시 정지).

중복 방 ID, 존재하지 않는 출구 목적지, 정의되지 않은 아이템/NPC 참조는 서버
시작 시 명확한 오류와 함께 거부됩니다.

## 구조

헥사고날 아키텍처. 도메인과 애플리케이션 계층은 TCP·SQLite·파일 형식 같은
어댑터 세부사항을 전혀 참조하지 않습니다.

```
cmd/mud-server          진입점: 어댑터 조립
internal/domain         게임 규칙과 상태 (Game, Effect, World, 전투, 파서)
internal/application    단일 게임 루프, 포트(CharacterRepository, NetGateway), 로그인 플로우
internal/adapter
  ├── tcp               Telnet 친화적 TCP 게이트웨이 (입력 큐잉, 느린 클라 퇴장)
  ├── sqlite            버전 관리 마이그레이션, 캐릭터 저장소
  └── worldfile         JSON 월드 로더
internal/e2e            실제 TCP 두 클라이언트 종단 간 테스트
configs/world.json      MVP 월드 정의
```

모든 상태 변경은 도메인 `Game`을 통과하고, 결과는 `Effect`(출력·방송·저장·종료)로
반환됩니다. 네트워크 고루틴은 입력을 큐에 넣을 뿐 상태를 건드리지 않으며, 게임
루프(단일 고루틴)가 입력·틱·예약 이벤트를 순차 처리합니다. 시계와 난수는 인터페이스로
주입되어 시간 기반 규칙(배회·재생성·전투 라운드)이 결정론적으로 테스트됩니다.

